# MOEX Screener v3.1

Скринер Московской биржи в реальном времени: 16 модулей сигналов, детектор роботов
(алгоритмических «ударов» по одной цене) и веб-дашборд, который обновляется каждые 5 секунд.
Источник данных — публичный MOEX ISS REST (`iss.moex.com`), доступ гостевой, ключ не нужен.

## Быстрый старт

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env          # при желании поправьте список бумаг и пороги

python moex_screener_v3_1.py --http
# дашборд: http://localhost:8080/dashboard.html
```

Без `--http` скринер печатает сигналы в консоль и параллельно пишет `data/screener.json`.
Дашборд можно поднять отдельно: `python server.py 8080` (он же отдаёт CORS-заголовки).

Другие варианты запуска:

```bash
python moex_screener_v3_1.py            # бесконечный цикл, вывод в консоль
python moex_screener_v3_1.py 3          # 3 цикла и выход
python moex_screener_v3_1.py --rest --http --port 9000
```

## Docker

```bash
docker compose up --build
# http://localhost:8080/dashboard.html
```

Образ уже запускает скринер с `--http` на порту 8080; сессии роботов сохраняются в
`./robot_db` (том), необязательный `./.env` подхватывается как `env_file`.
Без compose: `docker run --rm -p 8080:8080 -v $(pwd)/robot_db:/app/robot_db moex-screener`.

## Архитектура

```
MOEX ISS REST ──► boardprice.json  (LAST/BID/OFFER/VOLTODAY/NUMTRADES) ─┐
              └► trades.json      (хвост ленты: время, цена, лот, B/S) ─┤
                                                                        ▼
                                          TickerState (история цен и сделок)
                                                                        │
           M01…M16 (каждый модуль смотрит в общее состояние) ◄───────────┘
                                                                        │
                         консоль + data/screener.json ──► dashboard.html
```

Особенности работы с ISS, которые учтены в коде:

* `trades.json` игнорирует `iss.limit`/`iss.sort` и отдаёт максимум 5000 сделок
  **с начала сессии**. Чтобы получить свежий хвост ленты, скринер берёт `NUMTRADES`
  из `boardprice.json` и запрашивает срез по `start=`.
* Время ISS — московское (`SYSTIME`); консоль и дашборд тоже показывают МСК,
  независимо от часового пояса машины.
* Отметка «свежести» роботов считается по биржевым сделкам, а не по системным
  часам: после закрытия сессии сессии не исчезают через 30 минут.

## Модули

| М1 | Кто торгуется | дневной оборот по бумаге |
| М2 | Скачок цены | изменение ≥ 0.3% за 60 с |
| М3 | Всплеск объёма | z-score объёма ≥ 3 |
| М4 | Мегасделки | сделки крупнее обычного |
| М5 | Толстые уровни | узкий/широкий спред, плотность в стакане |
| М6 | Айсберг-радар | повторяющиеся объёмы на одном уровне |
| М7 | Айсберг (по одному) | то же для одной бумаги |
| М8 | Роботы (радар) | периодические минимальные удары у спреда |
| М9 | Открытый интерес | OI по фьючерсам (обновление раз в 5 мин) |
| М10 | Арбитраж | спред обычка/преф + z-score fair price |
| М11 | След алгоритма | сессии объёмных всплесков |
| М12 | Скальпинг | сделка ≥ 2× среднего размера |
| М13 | Раскачка | диапазон цены за окно |
| М14 | Отрыв от средней | отклонение от VWAP |
| М15 | Крупные деньги | дневной объём выше порога |
| М16 | Валюты | оборот на валютной секции |

### Как определяется робот (М8)

Робот — это серия **однотипных минимальных сделок по одной цене**. Сделки берутся
только реальные, из `trades.json`. Сессия заводится, если:

1. по одной цене прошло `ROBOT_MIN_REPEATS` (по умолчанию 3) и больше сделок;
2. медианный интервал между ними попадает в `ROBOT_STRIKE_MIN_SEC … ROBOT_STRIKE_MAX_SEC`
   (6–90 с);
3. медианный размер сделки ≤ `ROBOT_QTY_MAX_FACTOR` × медианы по бумаге;
4. цена лежит в зоне спреда ± `SPREAD_ZONE_FACTOR` × спред.

Сессия попадает в таблицу «Роботы» как **ACTIVE** только после
`ROBOT_MIN_LIFETIME_MIN` минут непрерывной работы. Направление (LON/SHR) — по
преобладанию агрессивных покупок или продаж на этом уровне. Сессии старше 30
биржевых минут удаляются из базы.

## Настройка (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `EQUITIES` | пусто | список бумаг TQBR; пусто — топ `EQUITIES_TOP_N` по обороту |
| `EQUITIES_TOP_N` | `20` | размер авто-списка бумаг |
| `FUTURES` / `FUTURES_TOP_N` | пусто / `30` | фьючерсы для М9 |
| `RENDER_SEC` | `5` | период опроса ISS |
| `ICEBERG_VOLUME_SPIKE_PCT` | `2.0` | порог всплеска для айсбергов |
| `SPREAD_ALERT_THRESHOLD` | `0.3` | порог спреда для М5 |
| `FAN_VOLUME_THRESHOLD` | `1000000` | порог «крупных денег» (М15) |
| `ROBOT_STRIKE_MIN_SEC` / `_MAX_SEC` | `6` / `90` | допустимый период робота |
| `ROBOT_MIN_REPEATS` | `3` | минимум ударов по одной цене |
| `ROBOT_QTY_MAX_FACTOR` | `2.0` | «минимальный» размер сделки, × медиана |
| `ROBOT_MIN_LIFETIME_MIN` | `10` | сколько минут робот должен прожить до ACTIVE |
| `SPREAD_ZONE_FACTOR` | `5.0` | ширина зоны вокруг спреда |
| `SOUND_ALERT_ENABLED` | `true` | звук при новом роботе (в контейнере выключен) |
| `ROBOT_DB_DIR` | `./robot_db` | каталог базы сессий роботов |

## Диагностика

* **Дашборд пишет «нет данных»** — он должен открываться по HTTP, а не через `file://`.
  Запускайте скринер с `--http` или `python server.py`.
* **«ДАННЫЕ УСТАРЕЛИ»** — в `data/screener.json` старый снимок: скринер не работает или
  ISS недоступен. Проверьте `curl -s https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities.json?iss.meta=off | head -c 200`.
* **Роботов нет** — это нормально на спокойном рынке: нужны минимум 3 ритмичных удара и
  10 минут жизни сессии. Уменьшите `ROBOT_MIN_LIFETIME_MIN` для быстрой проверки.
* **Пустые цены/объёмы** — торговая сессия закрыта; `boardprice` отдаёт последние значения,
  сделки в `trades.json` не обновляются.

## Ограничения

* Только акции TQBR (фьючерсы — только открытый интерес, валюта — только оборот).
* WebSocket-подписка MOEX (стакан/сделки в реальном времени по лицензии) в v3.1
  не используется: все данные — публичный REST с задержкой и лимитом в 5000 записей на страницу.
* Данные не являются инвестиционной рекомендацией.
